# WebScribe v0.1.6

本次修复荣耀开发者平台文档标题取错的问题，修正「内容无变化则跳过」的适用前提，
并把链接数量档位提高到 200。

## 修复

### 文档标题改为按内容结构判断

**现象：** 抓取荣耀开发者平台的文档时，标题取成了 `功能描述`（正文第一个小节），
而实际应该是 `锁屏、桌面、桌面小组件联动`。

**原因（经实地核查）：**

1. 荣耀的文档站**不用 `<h1>` 渲染标题**，正文标题与小节标题**都是 `<h3>`**：

   ```
   h3  功能描述      ← 正文第一个小节，不是标题
   h3  版本限制
   h3  应用场景
   ```

   只看标签层级无法区分哪个是标题。

2. 页面确实有一个承载标题的元素，但它是：

   ```html
   <div class="document-title">
     <span class="title">锁屏、桌面、桌面小组件联动</span>
     <span class="document-title-summary-button">智能摘要</span>
   </div>
   ```

   **外层 `div` 与内层 `span` 都带「title」命名**，而外层会把旁边的「智能摘要」
   按钮文字一并带上 —— 直接取外层就会得到 `锁屏、桌面、桌面小组件联动智能摘要`。

3. 页面上还好几个带 `title` 类名的元素其实都是**导航菜单**
   （`div.changeMore > div.title` 里的「应用分发」「游戏分发」……），
   以及一个智能客服弹窗的标题。**它们全都不是用 `<nav>`/`<header>` 标签写的**，
   而是 `div#header`、`.menu-title` 这类 class/id。

**修复：** 标题识别不再依赖 HTML 标签，改为按内容结构判断：

- 排除所有**站点外壳**区域 —— 既看 `<nav>/<header>/<footer>/<aside>` 标签，
  也看 class/id 里的 `nav`、`menu`、`sidebar`、`header`、`dialog`、`modal`
  等命名，导航菜单与弹窗因此被排除
- 候选之间是嵌套关系时**只取最内层**，避免把旁边的按钮文字带上
- 前面两步都找不到时，退回正文开头的标题

**效果（同一批真实页面实测）：**

| 站点 | 修复前 | 修复后 |
|---|---|---|
| 荣耀 全局持久化 | 功能描述 | **锁屏、桌面、桌面小组件联动** |
| 荣耀 文本 | 功能描述 | **文本-Text** |
| OPPO 开发者协议 | OPPO开发者服务协议 | OPPO开发者服务协议（不变） |
| 华为 主题引擎 | 变量：全局变量\<GlobalVariable\> | 变量：全局变量\<GlobalVariable\>（不变） |

### 「内容无变化则跳过」增加前提

**现象：** 换了保存目录后重新抓取，任务全部显示「已跳过」，保存目录里却没有
任何文档。

**原因：** 判定「已抓取过」只看内容指纹，没有确认上次产出的文档是否还在。

**修复：** 跳过前先检查 —— **上次产出的文档必须仍在当前保存目录里**；
换了保存目录、或文件被删除/移动时，一律重新抓取。

## 调整

**链接数量档位扩展为 10 / 50 / 100 / 150 / 200**，便于一次处理更多文档。

> 提醒：同一站点是串行抓取的（每次请求间隔至少 1 秒），200 条同站至少需要
> 200 秒纯等待，且撞上限流或验证码的概率也随之上升。界面上会按同站条数
> 给出最短耗时提示。
