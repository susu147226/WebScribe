# WebScribe v0.1.4

本次修复「同一站点的文档标题全都一样」的问题，并新增链接列表的记忆/导入导出、
以及内容无变化时自动跳过。

## 修复

### 文档标题取自页面自身，而不是网页的 `<title>`

**现象：** 抓取 OPPO、vivo 开放平台的文档时，每篇文档的标题**完全相同**，
文件名也全都一样。

**原因（经实地核查）：**

1. 这类文档站的 `<title>` 是**站点级**的固定文案。实测两个不同的 OPPO 文档页：

   ```
   /new/developmentDoc/info?id=10449  →  <title>OPPO 开放平台-OPPO开发者服务中心</title>
   /new/developmentDoc/info?id=11139  →  <title>OPPO 开放平台-OPPO开发者服务中心</title>
   ```

2. 页面真正的名字在正文的 `<h1>` 里（`OPPO开发者服务协议`、`OPPO 开放平台个人信息保护政策`）。

3. 但 Readability 的 `_headerDuplicatesTitle` 用 0.75 的文本相似度判断
   「这个标题与文章标题重复」，把这类 h1 一并删除 —— `OPPO开发者服务协议` 与
   `OPPO 开放平台-OPPO开发者服务中心` 因共享 `OPPO`、`开发者` 等词而被误判。
   等到 Readability 之后再找，页面标题已经没了。

**修复：** 在交给 Readability **之前**先取出页面的 `<h1>` 作为文档标题。
取值优先级为：

1. 页面自己的 `<h1>`
2. 提取后正文开头的标题
3. Readability 从 `<title>` 推出的标题
4. `<title>` 本身

**效果（同一批真实页面实测）：**

| 页面 | 修复前 | 修复后 |
|---|---|---|
| OPPO 文档 A | OPPO 开放平台-OPPO开发者服务中心 | `OPPO开发者服务协议` |
| OPPO 文档 B | OPPO 开放平台-OPPO开发者服务中心 | `OPPO 开放平台个人信息保护政策` |
| 华为文档 | 变量：全局变量\<GlobalVariable\>-基础功能-HarmonyOS 5.0及以上版本主题引擎规范-… | `变量：全局变量<GlobalVariable>` |

后两行原本也带着一长串栏目后缀——每页都相同，只是不像 OPPO 那样完全一致，
因此此前没有暴露出来。

作为标题的 h1 会从正文中移除，不会重复出现。

## 新增

### 链接列表自动记住，并可导出 / 导入

- **自动记住**：列表变化后自动存到本机，下次启动自动恢复，首行会提示
  「已恢复上次的 N 条链接」
- **导出**：把当前列表存为文本文件（一行一个链接）
- **导入**：从文本文件读回并并入当前列表，超出上限时会明确提示

清空列表后存档也会被清空，重启不会又冒出旧内容。

### 内容无变化时跳过

再次抓取同一链接时，若抓到的正文与上次**完全一致**，判定为已爬取过并跳过，
不再重复写入或追加：

- 界面上该条显示为「已跳过」并注明原因
- 任务结束时汇总提示「N 条链接的内容与上次完全一致，已跳过」
- 比对的是标题与正文内容；**爬取时间不算内容**，因此仅时间不同不会触发重新写出
- 日志的收尾记录也会带上跳过条数

判定结果与本机已有的合并记录放在同一份文件里，界面上的「清除合并记录」
会一并清除——清除后不再追加、也不再跳过。

## 新增排查工具

`crawler/tools/` 下有三个小工具，用于日后遇到类似站点时快速定位：

| 工具 | 用途 |
|---|---|
| `title-check.mjs` | 检查一批页面的标题是否被误取成站点名 |
| `dom-probe.mjs` | 查看页面渲染后标题的标记方式（h1？还是别的元素） |
| `readability-probe.mjs` | 查看 Readability 对页面标题做了什么 |

用法：`node tools/title-check.mjs <列表页或文档页 URL>`
