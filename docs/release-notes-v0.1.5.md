# WebScribe v0.1.5

修复「文档正文里的小节标题大量丢失」的问题。

> 若您抓取的是开发者文档站（OPPO、vivo 等），建议升级：该问题会让产出的
> Markdown 只剩正文段落、所有小节标题消失，文档结构完全丢失。

## 修复

### 正文标题被 Readability 当作「页头」删除

**现象：** 抓取 OPPO 文档时，产出的 Markdown 里**一个小节标题都没有**；
正文段落都在，标题全没了。

**原因（经实地核查，分三层）：**

1. 该文档站把正文标题的 id 依次命名为 `header-0`、`header-1`、`header-2`……
2. Readability 有一份「可疑元素」正则，用于剥掉页面顶部的导航栏、页脚等，
   其中包含 **`header`** 一词。节点的 id 或 class 命中该正则就会被整块删除。
   `id="header-1"` 因此被当成页头。
3. 结果：`#wikiContent` 下 173 个有文本的子元素里，161 个正常保留，
   被丢掉的 12 个**恰好是全部小节标题**。

**定位过程（供日后遇到类似站点参考）：**

- 逐个核对 `#wikiContent` 的直接子元素是否出现在结果里 → 锁定 12 个标题
- 关闭 Readability 的 `FLAG_STRIP_UNLIKELYS` 开关 → 12 个标题全部回来
- 据此确认是「可疑元素」正则所致，而非内容不足或拼接问题

**修复：** 在交给 Readability **之前**，把标题元素（h1–h6）上会触发误判的
id / class 换掉：

- id 整体换成一个不含触发词的新值（**不能只在原名前加前缀**——`ws-header-1`
  里依旧带着 `header`，仍会被命中）
- class 里逐个 token 检查，只丢掉触发误判的那些，其余保留
- 同步指向该标题的页内锚点，不破坏文档内的跳转
- **只处理标题元素**：导航栏里的 `class="header"` 本来就该被剥掉，不替它保留
- 正则直接取用 Readability 自身的 `REGEXPS`，不另抄一份，以免它升级后两边失配

**效果（同一页面实测）：**

| | 修复前 | 修复后 |
|---|---|---|
| 正文标题数 | 0 | **12** |
| 文档标题 | OPPO开发者服务协议 | OPPO开发者服务协议 |
| 正文段落 | 正常 | 正常 |

12 个小节标题（`1. 定义` … `附件一：廉洁协议`）全部保留，且作为文档标题的 h1
不会在正文里重复出现。

## 测试情况

399 项测试全部通过：

| 套件 | 数量 |
|---|---|
| Rust 单元测试 | 147 |
| crawler 单元测试 | 147 |
| 端到端集成测试 | 53 |
| 前端单元测试 | 52 |

本次新增 13 项，覆盖：id 含 `header` 的标题被换名、换名后确实不再命中正则、
页内锚点同步、不指向该标题的锚点不受影响、新 id 不与既有 id 冲突、
class 部分命中时只丢触发词、**只处理标题不动导航**、命中「可能是正文」的词时不改动、
以及端到端的小节标题保留。

## 新增排查工具

`crawler/tools/heading-probe.mjs` —— 对比「渲染后 DOM 里的标题」与
「提取结果里的标题」，一眼看出丢了哪些。用法：

```
node tools/heading-probe.mjs <URL>
```
