# WebScribe v0.1.1

修复 v0.1.0 中导致抓取完全不可用的缺陷，并修复真实文档站内容被丢弃的问题。

> **使用 v0.1.0 的用户请务必升级。** 该版本点击「开始抓取」后会永久卡在「等待中」且不显示任何错误。

## 修复

### 1. 首次抓取永久卡死（严重）

**现象：** 粘贴 URL 后点击「开始抓取」，任务列表停在「等待中」不动，界面无任何错误提示。

**原因：** Rust 的临时量生命周期陷阱。原代码写成：

```rust
match state.sidecar.lock().await.clone() {   // ← 锁守卫是 match 的匹配对象（临时量）
    None => {
        *state.sidecar.lock().await = Some(...)   // ← 再次加锁 → 永久自死锁
    }
}
```

`match` 的匹配对象是临时量，其生命周期延续到**整个 match 表达式结束**，因此 `None` 分支里第二次加锁时第一把锁尚未释放。由于命令永不返回，前端也拿不到任何错误。

**修复：** 改为「先取出锁值、再判断」，并抽出 `AppState::ensure_sidecar` 统一处理。已补充回归测试，明确记录该陷阱与正确写法。

### 2. PDF 输出会挂起（同类问题）

收尾逻辑 `finalize_run` 需要等待 PDF 渲染应答，而应答只能由同一个 stdout 读取协程处理。在原实现中它被直接 `await`，导致读取协程自我阻塞、PDF 输出永久挂起。现改为另起任务执行。

### 3. 真实文档站的表格未转换为 Markdown（内容质量）

**现象：** 抓取开发者文档时，页面上的表格全部以原始 HTML 输出，并残留大量 `id="ZH-CN_..."` 属性。实测某页 21 张表格无一转换。

**原因：** 这类站点把表头行也写成 `<td>`（没有 `<thead>`、没有 `<th>`）。Turndown 的 GFM 表格规则要求首行单元格是 `<th>`，否则放弃转换、整表降级为原始 HTML。

**修复：** 转换前把无 `<thead>` 表格的首行提升为 `<th>` 并补齐结构；同时去掉单元格内唯一 `<p>` 的包裹（否则块级元素会在表格行中插入换行），并清理表格内部的 `id` 属性。

### 4. 装饰性容器内的代码块被整段丢弃（内容质量）

**现象：** 同一页面的 3 段示例代码在产物中完全消失。

**原因：** 文档站把代码包在装饰性容器里
（`div.highlight-scroll-div > div.highlight-div > pre`），Readability 的
`_cleanConditionally(articleContent, "div")` 会把这类「只有一个子元素、既无段落也无图片」的 div 判为无用内容删除，其中的 `<pre>` 随之消失。

此外这类站点把代码写作 `pre > ol.linenums > li`（已被 highlight.js 着色），而不是 Turndown 要求的 `pre > code`，即便侥幸保留也不会转成围栏代码块。

**修复：** 在 Readability 之前拆掉只起排版作用的包裹 div，并把代码还原为 `pre > code`。

**关于语言标注：** 这类站点的 `language-vbnet` / `language-perl` / `language-php-template` 是 highlight.js **自动识别**的结果（内容实为 XML 主题代码）。把这种猜测写进 Markdown 会产生误导，因此带 `hljs` 标记的代码块不输出语言；作者显式声明的语言仍然保留。

### 5. 多 URL 任务行的 key 与事件不匹配

**现象：** URL 若在规范化后与原文不同（末尾斜杠、默认端口、大写主机名等），任务行会一直停在「等待中」。

**原因：** 任务行的 key 取自用户原始输入，而所有进度与结果事件携带的是 Rust 规范化后的 key。

**修复：** 任务行改用规范化 key；原始 URL 仍原样展示。

## 其它改进

**新增结构化日志。** 此前 `logging.rs` 已实现但未接线，导致问题难以诊断。现在日志写入
`%APPDATA%\com.webscribe.app\logs\webscribe-YYYYMMDD.jsonl`，记录任务开始/结束、子进程启动、错误类型等；
URL 与凭据仍按原规则脱敏。界面右上角「运行时就绪」徽章的悬停提示会显示日志路径。

## 产物

| 文件 | 说明 |
|---|---|
| `WebScribe-Setup-x64.exe` | 安装版，当前用户安装，无需管理员权限 |
| `WebScribe-Portable-x64.zip` | 便携版，解压后双击 `WebScribe.exe` |

两个版本均已内嵌 Node 运行时与 Chromium，无需安装任何开发环境。

> 若您此前把 v0.1.0 安装在自定义目录（例如 `D:\webscribe`），安装 v0.1.1 时请留意安装向导中的目录选择，
> 或在安装前先卸载旧版本。
