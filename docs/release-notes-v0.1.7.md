# WebScribe v0.1.7

本次修复「论文摘要、小说短章等短正文被误判为无法获取正文」的问题，
并让 WAF 挑战与中文验证码得到正确的错误提示。

## 修复

### 短正文不再被误判为「无法获取正文」

**现象：** 抓取论文摘要、小说短章、诗歌时，报「无法获取正文内容」。

**原因：** 程序要求正文至少 **200 字符**才算「提取成功」。但论文摘要、小说
短章、诗歌等正当内容常常不足一两百字——它们走完 HTTP 与浏览器渲染两条路径后
仍然「不达标」，最终被报成「无法获取正文」。实测一个 150 字的摘要页、一个
12 字的噪声页，前者被误杀、后者才该被拒。

**修复：** 把正文充分性的底线从 200 字符降到 **50 字符**：

- 150 字的摘要、100 字的中文摘要、50 字的短章现在都能正常提取
- 50 字符的底线足以排除纯导航、版权声明、空白页等零星噪声
- 浏览器回退渲染的判定阈值同步调整，不再把短正文当成「没渲染出来」

### WAF 挑战与中文验证码得到正确提示

**现象：** 抓取起点的小说章节、知网的论文时，报「无法获取正文内容」，让人
误以为程序坏了。实际是网站的反爬机制，与正文提取无关。

**排查结论（实地验证）：**

- **起点**：HTTP 202 + 209 字节的空页面，只带一个 `probe.js` 探测脚本，
  靠浏览器执行 JS 才放行——这是 WAF JS 挑战
- **知网**：页面只有 20 字节的「请完成安全验证 请依次点击【我,看,话】」——
  这是点击式人机验证
- **51cto 等普通文章站**：正常，4494 字符正文一次到位（对照验证提取逻辑无问题）

**修复：**

- 识别 WAF 探测脚本（`probe.js`）→ 报「访问验证（Challenge）」
- 识别中文人机验证（「请完成安全验证」「请完成行为验证」等祈使句）→ 报「检测到验证码」
- 只匹配明确的祈使句，不误伤正文里「介绍验证码」的普通文章

这样，起点、知网这类站点会明确提示「需要用户手动处理」，而不是让人误以为
正文提取坏了。

> 说明：知网的 PDF 阅读页（正文在 PDF 文件里，HTML 只有阅读器框架）不在本次
> 处理范围内——本工具定位是「网页正文提取」，PDF 文件本身需另行下载打开。
